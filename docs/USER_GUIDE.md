# 1. VisionLinkとは

VisionLink は、端子台の配線検査を iPhone などのカメラとAIで支援するWebアプリケーションです。

基本処理は次の順です。

1. iPhoneカメラで端子台を撮影します。
2. YOLOで端子番号・左右Tubeを検出します。
3. 検出したBBox内部を切り出します。
4. 必要な対象だけOCR向きを補正します。
5. PaddleOCRで文字を読み取ります。
6. CSVの検査データと照合します。
7. 一致した項目を検査テーブル上で消し込みます。

VisionLinkでは、単に「画面内に同じ線番が存在するか」だけでは判定しません。

**中央の端子番号（Label / nmb）を基準に、その端子の左側にあるTubeをL、右側にあるTubeをRとして対応付けて検査します。**

---

# 2. 検査対象を理解する

## 2.1 1端子の基本構成

1端子の物理的な位置関係は次のとおりです。

```text
左側                                         右側

 Tube（L） ─────── 端子（Label / nmb） ─────── Tube（R）
   線番                    端子番号                    線番
```

検査の基本単位は、**Tube ― 端子 ― Tube** の3要素です。

### L

端子の左側に接続されたTubeです。Tubeには線番が印字されています。

### Label / nmb

中央の端子番号です。通常は `1`、`2`、`3` のような数字です。

### R

端子の右側に接続されたTubeです。こちらも線番が印字されています。

## 2.2 重要な考え方

VisionLinkが確認したいのは、次の3点です。

1. **端子番号が正しいか**
2. **その端子の左Tubeが正しいか**
3. **その端子の右Tubeが正しいか**

したがって、同じ線番が別の端子に存在していても、その端子の左右にない場合は本来の検査対象とは扱いません。

# 3. 端子台の置き方とiPhoneの向き

## 3.1 端子台は縦向きに読み込む

実際の検査では、端子台の長手方向がiPhone画面の上下方向になるように撮影します。

画面内では次のように見える状態が基本です。

```text
                 iPhone画面

       左Tube列      Label列      右Tube列

        H0D4F8V          6          H0D4F8V
        P5X9Q2           7          P5X9Q2
        D5A2L9F4         8          D5A2L9F4
        V2C8M            9          V2C8M
```

中央に端子番号列、その左側にL Tube列、右側にR Tube列が並びます。

## 3.2 「縦向き」の意味

端子台を縦に撮影するからといって、1端子の対応が「上Tube ― 端子 ― 下Tube」になるわけではありません。

**検査上の対応は、常に同じ高さの L ― Label ― R です。**

## 3.3 良い撮影状態

次の状態を目標にしてください。

- 中央のLabel列が画面内に連続して見えている
- 左右Tubeの文字が途中で切れていない
- 端子台が画面に対して大きく斜めになっていない
- 反射で文字が白飛びしていない
- ピントが合っている
- BBoxが対象文字をほぼ覆っている

## 3.4 避けるべき撮影状態

次の状態ではOCR精度や対応付け精度が低下しやすくなります。

- Label列が画面外へ切れている
- 左右どちらかのTube列がほとんど見えていない
- iPhoneを極端に斜めから向けている
- 強い照明反射が文字上にある
- カメラを激しく動かしている
- 端子台まで遠すぎて文字が小さい
- 近すぎてBBox対象が画面外へ切れている

# 4. 検査画面の構成

検査画面は大きく次の領域に分かれます。

```text
┌─────────────────────────────┐
│ ① カメラ映像・BBox          │
├─────────────────────────────┤
│ ② L / Label                 │
│    カメラ開始・停止          │
│    検査開始・停止            │
├─────────────────────────────┤
│ ③ 検査テーブル進捗          │
│    9 / 100 など              │
├─────────────────────────────┤
│ ④ 製番・番号・端子台選択    │
├─────────────────────────────┤
│ ⑤ L / Label / R / ALL       │
│    各端子の検査結果          │
├─────────────────────────────┤
│ ⑥ 作業者確認 / 完了         │
└─────────────────────────────┘
```

## 4.1 カメラ映像

端子台のライブ映像を表示します。

検出された対象にはBBoxが表示されます。

## 4.2 Lボタン

左TubeのOCR向きを180度補正するためのボタンです。

## 4.3 Labelボタン

中央の端子番号を90度補正するためのボタンです。

## 4.4 カメラ開始 / 停止

カメラ映像そのものを開始・停止します。

## 4.5 検査開始 / 停止

YOLO検出・OCR・照合による検査処理を開始・停止します。

**カメラ開始と検査開始は別操作です。**

## 4.6 進捗

`9 / 100` のように表示します。

- 左側: 完了済み件数
- 右側: 検査対象総数

進捗だけで合否を判断せず、必ず検査テーブルも確認してください。

## 4.7 再読込

CSVの検査データを再度読み込みます。

## 4.8 完了

検査完了時に使用します。

## 4.9 作業者確認

AI/OCRの自動判定とは別に、作業者が結果を確認したことを記録するための項目です。

# 5. 検査前チェック

検査開始前に次の内容を確認してください。

| 確認項目 | 正常な状態 |
|---|---|
| ネットワーク | VisionLinkへアクセスできる |
| 製番 | 検査対象と一致している |
| 盤・番号 | 対象と一致している |
| 端子台 | 対象端子台名と一致している |
| CSV | 検査テーブルが正しく表示されている |
| カメラ | ライブ映像が表示される |
| 端子台向き | 長手方向が画面上下方向 |
| Label列 | 中央に見えている |
| 左Tube | 左側に見えている |
| 右Tube | 右側に見えている |
| L補正 | 左Tubeが逆さならON |
| Label補正 | nmbが右90度倒れならON |

対象製番や端子台を間違えた状態で検査を開始すると、正しい製品でも照合結果が一致しません。

# 6. 検査の基本手順

## Step 1: 検査対象を選択する

製番、盤・番号、端子台を選択します。

選択後、検査テーブルに期待する線番とLabelが表示されていることを確認します。

## Step 2: カメラを開始する

`カメラ開始` を押します。

ライブ映像が表示されたら、端子台を縦向きに映します。

## Step 3: BBoxを確認する

次の3列にBBoxが出ているか確認します。

- 左Tube
- 中央Label
- 右Tube

BBoxが大きく対象文字から外れている場合は、検査開始前にカメラ位置を調整します。

## Step 4: OCR向きを決める

実際の文字方向を見て、必要に応じて `L` / `Label` を設定します。

### 左Tubeが逆さ

`L` をONにします。

### nmbが右へ90度倒れている

`Label` をONにします。

## Step 5: 検査を開始する

`検査開始` を押します。

検査中は、カメラ位置をできるだけ安定させます。

## Step 6: 消込を確認する

検査テーブルの `L / Label / R / ALL` を確認します。

一部だけ緑になった場合は、その項目だけ一致した状態です。

## Step 7: 未完了行を読み取る

未完了の端子がある場合は、iPhoneをゆっくり移動して対象を画面中央付近へ持ってきます。

## Step 8: 最終確認する

全対象が完了したら、未完了行・NG表示・誤読がないか確認します。

## Step 9: 作業者確認・完了

必要に応じて `作業者確認` をチェックし、`完了` を押します。

---

# 7. Lボタンの使い方

## 7.1 Lとは

Lは、**左TubeだけをOCRするときの回転補正**です。

## 7.2 OFF時

左TubeのBBoxから切り出した画像を、そのままOCRします。

## 7.3 ON時

左TubeのOCR用cropだけを**180度回転**してOCRします。

```text
元カメラ画像
      ↓
左TubeをYOLO検出
      ↓
BBox領域をcrop
      ↓
180度回転
      ↓
OCR
```

## 7.4 回転するもの / しないもの

| 対象 | L ON時 |
|---|---|
| カメラ映像 | 回転しない |
| YOLO BBox | 回転しない |
| 画面レイアウト | 回転しない |
| OCR用crop | 180度回転する |

## 7.5 いつONにするか

左Tubeの印字が、画面上で完全に逆さに見える場合です。

## 7.6 ONにしない方がよい場合

左Tubeがすでに正立して読める場合はOFFのままにします。

不要な回転補正を入れるとOCR精度を下げる可能性があります。

---

# 8. Labelボタンの使い方

## 8.1 Labelとは

Labelは、中央の端子番号（nmb）のOCR方向を補正するボタンです。

## 8.2 想定している状態

端子台を縦向きにした結果、端子番号の数字が画面上で**右へ90度倒れている**状態です。

## 8.3 ON時の処理

```text
画面上のnmb
      ↓
右へ90度倒れている
      ↓
BBox領域をcrop
      ↓
左へ90度回転
      ↓
数字を正立
      ↓
OCR
```

## 8.4 回転するもの / しないもの

| 対象 | Label ON時 |
|---|---|
| カメラ映像 | 回転しない |
| オレンジBBox | 回転しない |
| BBox座標 | 変わらない |
| OCR用crop | 左へ90度回転する |

## 8.5 Label ON中の注意

Label ON時は、回転補正したnmb結果を検査へ使用します。

「補正していないnmb結果」と「補正済みnmb結果」が混在して誤判定しないよう、Label回転を有効にした状態では回転対象の結果を基準に扱います。

# 9. BBox・色・矢印の見方

## 9.1 BBoxとは

BBoxはYOLOが検出した対象領域を表す枠です。

BBoxは**OCR結果そのものではありません**。

BBoxが出ていることは「対象候補を検出できている」ことを意味します。

## 9.2 色の意味

| 色 | 主な対象 | 意味 |
|---|---|---|
| 紫 | L Tube | 180度OCR補正対象 |
| オレンジ | Label / nmb | 90度OCR補正対象 |
| 水色 | 通常対象 | 回転補正なし |

## 9.3 矢印の意味

回転補正を使用している場合、対象となる最上段BBox付近に読取方向を示す矢印を表示します。

矢印は、**OCR用cropをどの向きへ補正しているか**を示します。

矢印の方向へBBoxそのものが動く、または回転するという意味ではありません。

## 9.4 BBoxを見るときのポイント

正常なBBoxは、対象文字列をほぼ覆っています。

次の場合は注意してください。

- 文字の半分しかBBoxに入っていない
- 隣のTubeまで大きく囲っている
- LabelなのにTubeの場所へ枠が出ている
- 同じ対象に複数の不自然なBBoxが重なっている

# 10. 端子番号と左右Tubeの対応付け

## 10.1 Labelが基準

VisionLinkは中央のLabel / nmbをアンカーとして左右Tubeを探します。

```text
左Tube         Label         右Tube

H0D4F8V          6           H0D4F8V
P5X9Q2           7           P5X9Q2
D5A2L9F4         8           D5A2L9F4
V2C8M            9           V2C8M
```

## 10.2 端子ごとの縦範囲

各端子に対応する縦方向の範囲は、隣接するLabel同士の中間位置を境界として決めます。

```text
──────── Label 5 / 6 の中間 ────────

   左Tube        [ Label 6 ]        右Tube

──────── Label 6 / 7 の中間 ────────

   左Tube        [ Label 7 ]        右Tube

──────── Label 7 / 8 の中間 ────────
```

## 10.3 左右判定

同じ端子帯の中で、

- Labelより左側 → L候補
- Labelより右側 → R候補

とします。

## 10.4 なぜこの方式なのか

単純に画面全体から同じ線番を探すと、隣の端子に同じ線番がある場合に誤対応する可能性があります。

Label位置を基準にすることで、**「何番端子の左右にある線番か」まで含めて検査**します。

# 11. 検査テーブルと消込の見方

検査テーブルは基本的に次の4列です。

| 列 | 内容 |
|---|---|
| `L` | 左Tube |
| `Label` | 端子番号 |
| `R` | 右Tube |
| `ALL` | 端子全体の完了状態 |

## 11.1 緑表示

CSV期待値と一致した項目です。

## 11.2 赤表示

不一致（NG）を示す表示です。

## 11.3 黒・通常表示

未検査・未確定・データなし等の状態です。

## 11.4 一部だけ消込された場合

例:

```text
L          Label        R          ALL

未完了       7          P5X9Q2      未完了
```

この場合、LabelとRは一致していてもLが未完了です。

端子全体の検査は完了していません。

## 11.5 ALLがOKになる条件

必要な `L / Label / R` が対象端子として正しく照合できたとき、その行のALLをOKとして扱います。

---

# 12. OK・NG・未完了の判断

## 12.1 OK

次の状態です。

- Labelが期待する端子番号と一致
- Lが期待する左Tube線番と一致
- Rが期待する右Tube線番と一致
- 端子の対応関係も正しい

## 12.2 NG

期待値とOCR結果が一致しない状態です。

NGが出た場合は、すぐに製品不良と断定せず、まず次を確認してください。

1. OCR誤読ではないか
2. BBoxが正しく対象を囲っているか
3. L / Label回転設定が正しいか
4. 対象製番・端子台が正しいか
5. 実物の線番が本当に異なるか

## 12.3 未完了

対象をまだ正しくOCR・照合できていない状態です。

未完了はNGとは異なります。

# 13. 実際の検査フロー

## 13.1 カメラ開始直後

確認すること:

- 端子台が縦向き
- Label列が中央
- 左右Tube列が見える
- BBoxが出る

この段階ではまだ検査結果がなくても問題ありません。

## 13.2 検査開始後

確認すること:

- OCR結果が更新される
- Label番号が正しく見えている
- 左右Tubeが対応する行へ反映される
- 進捗が増える

## 13.3 OKが進んでいる場合

緑表示が増え、ALLがOKになる行が増えていきます。

iPhoneを急に動かさず、未検査の端子へゆっくり移動します。

## 13.4 NGが出た場合

その場でカメラを安定させ、対象行を確認します。

次の順で切り分けると安全です。

1. Label番号
2. 左Tube OCR
3. 右Tube OCR
4. L / Label回転状態
5. CSV期待値
6. 実物印字

---

# 14. うまく読めないとき

## 14.1 Labelが読めない

確認してください。

- Labelボタンは正しい状態か
- 数字が右90度倒れているならLabel ONか
- Label列が画面中央付近にあるか
- 数字全体がBBox内にあるか
- 反射していないか
- ピントが合っているか

## 14.2 左Tubeが読めない

- 左Tubeが逆さならL ON
- 正立ならL OFF
- BBoxが線番全体を含んでいるか
- Tubeが極端に斜めになっていないか

## 14.3 右Tubeが読めない

右Tubeは通常回転対象外です。

まず撮影角度・ピント・反射を確認してください。

## 14.4 BBoxは出るがOCR結果が出ない

BBox検出とOCRは別処理です。

次を確認してください。

- 文字が小さすぎないか
- BBox内に文字全体が入っているか
- 画像がぶれていないか
- OCR向きが正しいか

## 14.5 OCRが安定しない

数秒間iPhoneを静止してください。

動かし続けるより、対象端子を一度画面中央付近で安定させる方が読みやすくなります。

---

# 15. 誤読・誤対応が疑われるとき

## 15.1 別端子の線番を拾っているように見える

まずLabel列を確認してください。

VisionLinkはLabel位置から端子ごとの検査帯を決めます。

Labelの検出位置が不安定だと、左右Tubeとの対応も不安定になる可能性があります。

## 15.2 同じ線番が複数ある

同じ線番が画面内に複数あっても、Labelとの位置関係で対応を決めます。

単純な文字列一致だけではありません。

## 15.3 nmbが違う番号に見える

Label OCR結果が誤っている場合は、そのLabelをアンカーにした左右対応も正しくない可能性があります。

その状態で無理に検査を進めず、撮影位置・Label回転・ピントを調整してください。

---

# 16. 検査終了時の確認

完了ボタンを押す前に次を確認してください。

- 対象製番は正しい
- 対象端子台は正しい
- 進捗に不自然な残りがない
- NG行が残っていない
- 未完了行が残っていない
- Label番号に不自然な誤読がない
- L / Rの線番が期待値と一致している
- 必要に応じて作業者確認を実施した

進捗が `100 / 100` であっても、現場運用上必要な確認を省略しないでください。

# 17. よくある質問

## Q1. Label ONにするとBBoxも90度回転しますか？

しません。

回転するのはOCRへ渡すcrop画像だけです。

## Q2. L ONにすると画面が逆さになりますか？

なりません。

左TubeのOCR用cropだけを180度回転します。

## Q3. 紫・オレンジ・水色は合否ですか？

違います。

主にOCR方向や対象種類を示すBBox色です。

合否は検査テーブル側で確認します。

## Q4. Labelだけ読めれば線番を検査できますか？

Labelだけでは端子全体は完了しません。

左右Tubeの照合も必要です。

## Q5. 左右のTubeが同じ線番でも両方読む必要がありますか？

はい。

左右それぞれがその端子の正しい位置に存在することを確認します。

## Q6. NGが出たら即不良ですか？

OCR誤読の可能性もあるため、BBox、OCR方向、撮影状態、CSV、実物を確認してください。

## Q7. カメラを横向きにしても使えますか？

Prototypeの基本運用は、端子台を縦向きに収める方法を前提としています。

---

# 18. Prototypeとしての注意事項

- 本版はPrototypeです。
- 端子台は基本的に縦向きで読み込みます。
- 1端子の物理的な関係は `Tube ― 端子 ― Tube` です。
- 画面上の検査関係は `L ― Label ― R` です。
- `L` は左TubeのOCR用cropを180度補正します。
- `Label` は右90度倒れたnmbを読むため、OCR用cropを左90度補正します。
- L / LabelをONにしてもBBox自体は回転しません。
- 検査画面は操作中に大きく揺れない固定的なレイアウトを前提としています。
- AI/OCR結果だけで最終的な品質保証を行わないでください。
- 誤認識を発見した場合は、対象端子、CSV期待値、OCR結果、可能であれば画像を記録してください。

# 19. 用語集

| 用語 | 意味 |
|---|---|
| Tube | 端子に接続された電線のチューブ。線番が印字されている |
| L | 端子左側のTube |
| R | 端子右側のTube |
| Label / nmb | 端子番号。通常は数字 |
| BBox | YOLOが検出した対象領域を示す枠 |
| OCR | 画像から文字を読み取る処理 |
| crop | BBox内部から切り出したOCR用画像 |
| CSV | システムに登録された検査期待データ |
| 消込 | OCR結果と期待値が一致した項目を検査済みとして反映すること |
| ALL | 1端子として必要な検査が揃った状態 |
| Prototype | 現場検証中の試作版 |
