## 6. Prototypeで意図的に残している設計課題

### FrontendとBackendの判定が別系統

現状:

```text
Backend
  judge_row() → InspectionRowState

Frontend
  checkReconcile.ts → L / Label / R / ALL
```

Prototypeでは画面消込をFrontend側で成立させています。
本番化時には、どちらを判定のSingle Source of Truthにするか決める必要があります。

### Label OCRの位置

Label ON時の90°補正は現在API層から `label_ocr.py` を呼び出します。
Prototypeとしては明示的で扱いやすい構造ですが、本番設計ではAI pipeline内への統合も候補です。

## 7. リリース判定の目安

### Prototype → 現場検証版

- 主要端子台で消込が安定
- L/Label操作が作業者に理解できる
- 誤消込の重大ケースがない
- 既知の制約が文書化されている

### 現場検証版 → 本番候補

- 認証/セキュリティ方針確定
- 検査履歴・監査要件確定
- 回帰テスト整備
- 障害時運用確定
- AI/OCR精度の受入基準確定
