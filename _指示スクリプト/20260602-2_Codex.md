次に、検出結果と検査テーブルの消込処理を追加してください。

目的:
CSVから読み込んだ検査テーブルを基準に、YOLO/OCRで検出した Label と Tube_L / Tube_R を照合し、検査済み行をUI上で消し込めるようにする。

対象:
- frontend/src/App.tsx
- frontend/src/api.ts
- frontend/src/types.ts
- frontend/src/styles.css
- 必要に応じて backend/app/schemas.py
- 必要に応じて backend/app/services/session_manager.py
- 必要に応じて backend/app/services/ai_pipeline.py

前提:
- 検査テーブルは CSV 由来で、以下の列を持つ。
  - tube_l
  - label
  - tube_r
- Web UI では以下の列で表示している。
  - ✔ | Tube_L | Label | Tube_R | ✔ | ALL☑
- OCR / YOLO の推論結果は frame-analyze response で取得できる。
- カメラ中央には赤いガイドラインがあり、画像幅の中心 x=50% を左右判定基準にする。
- 推論結果には、Label / nmbシリーズ / Tube のBBoxとOCR文字列が含まれる想定。

実装要件:

1. 検査テーブル未セット時の操作制限

UI上の検査に関わる以下ボタンは、検査テーブルがセットされるまで押せないようにしてください。

対象ボタン:
- カメラ開始
- Rotate OCR: ON/OFF
- 検査開始
- 必要であれば検査停止も状態に応じて制御

条件:
- selectedSerial
- selectedBoard
- selectedTerminal
- checkTable rows が1件以上

上記が揃っていない場合:
- ボタン disabled
- 可能なら title に「検査テーブルを選択してください」と表示

例:
```tsx
const isCheckTableReady =
  selectedSerial &&
  selectedBoard &&
  selectedTerminal &&
  checkRows.length > 0;
```

2. チェック対象は、画面にセットした検査テーブルのみ

照合は、現在 UI に読み込まれている検査テーブルに対して行ってください。

* 別の製番・盤番号・端子台のデータは参照しない
* 検査テーブルが切り替わったら、消込状態もリセットする
* selectedSerial / selectedBoard / selectedTerminal が変わったら、検査状態を初期化する

3. チェックは Label の値を基準に行う

検出した nmb シリーズの値を Label として扱い、検査テーブルの `label` 列と照合してください。

想定:

* nmbシリーズ検出結果 = Label候補
* OCR文字列が `NMB-001` や `1` などで返る
* 検査テーブルの `label` と一致する行を探す

照合時は文字列を正規化してください。

正規化例:

* trim
* 全角半角の必要があれば将来対応
* 大文字化
* 空白削除
* ハイフンなどはまず維持
* 必要なら `normalizeCheckText()` として関数化

```ts
function normalizeCheckText(value: string): string {
  return value.trim().toUpperCase().replace(/\s+/g, "");
}
```

4. 検出結果から Label / Tube を分類する

frame-analyze response から、以下を抽出してください。

* Label候補:

  * class_name / role が `label`, `nmb`, `number`, `terminal`, `terminal_label` など
  * または OCR text が検査テーブルの label 値と一致するもの

* Tube候補:

  * class_name / role が `tube`, `tube_l`, `tube_r`, `left_tube`, `right_tube` など
  * または Label候補の左右近傍にあるOCR結果

既存の yolo_results / ocr_results のデータ構造に合わせて実装してください。
class_name / role が不足している場合は、bbox位置とOCR文字列で暫定的に対応してください。

5. Label に一致する検査テーブル行を探す

検出した Label候補の text を正規化し、検査テーブルの `label` と一致する行を探してください。

例:

```ts
const detectedLabel = normalizeCheckText(labelResult.text);
const row = checkRows.find(
  row => normalizeCheckText(row.label) === detectedLabel
);
```

一致する行がない場合:

* 消込しない
* debug log に unmatched label として出す

6. Label の左右にある Tube を探す

一致した Label BBox を基準に、左右にある Tube 検出結果を探してください。

判定:

* Tube BBox の中心 x が Label BBox の中心 x より左なら左Tube候補
* Tube BBox の中心 x が Label BBox の中心 x より右なら右Tube候補
* さらに中央ガイドラインも使う

今回の仕様では:

* ガイドラインより左にある Tube は Tube_L と照合
* ガイドラインより右にある Tube は Tube_R と照合

ガイドライン:

```ts
const guideX = cameraDisplayWidth / 2;
```

または正規化座標の場合:

```ts
const guideX = 0.5;
```

7. Tube_L の照合

検出した Tube がガイドラインより左側にある場合:

* 同じ Label 行の `tube_l` と照合
* 一致したら、その行の Tube_L を検査OKにする
* UI上で Tube_L の文字列を緑色にする

条件:

```ts
tubeCenterX < guideX
normalizeCheckText(tubeText) === normalizeCheckText(row.tube_l)
```

一致:

* row.tube_l_status = "OK"
* Tube_L セルに green class を付与

不一致:

* row.tube_l_status = "NG" または未変更
* 今回は誤検出でNG固定にしすぎないよう、まずは未変更でも可
* debug log に mismatch として出す

8. Tube_R の照合

検出した Tube がガイドラインより右側にある場合:

* 同じ Label 行の `tube_r` と照合
* 一致したら、その行の Tube_R を検査OKにする
* UI上で Tube_R の文字列を緑色にする

条件:

```ts
tubeCenterX > guideX
normalizeCheckText(tubeText) === normalizeCheckText(row.tube_r)
```

一致:

* row.tube_r_status = "OK"
* Tube_R セルに green class を付与

9. Label列の完了表示

同じ行で以下が両方OKになったら、その行は左右チェック完了とします。

条件:

* tube_l_status === "OK"
* tube_r_status === "OK"

このとき:

* Label列の文字列も緑色にする
* 行の背景をグレーにする
* all_status = "OK"
* confirm_status = "OK" または row_completed = true

表示:

* Tube_L: 緑文字
* Tube_R: 緑文字
* Label: 緑文字
* 行背景: グレー
* ALL☑: OK
* 右側✔: ◯
* 左端✔: ◯

10. 行状態の型を拡張

frontend/src/types.ts の CheckRow を拡張してください。

例:

```ts
type CheckStatus = "PENDING" | "OK" | "NG";

type CheckRow = {
  tube_l: string;
  label: string;
  tube_r: string;
  tube_l_status?: CheckStatus;
  label_status?: CheckStatus;

```

既存の left_status / confirm_status / all_status がある場合は、それを活かしても構いません。

11. 検出結果を受け取るたびに消込処理を実行

frame-analyze response を受け取った後に、検査テーブルに対して消込処理を実行してください。

例:

```ts
const updatedRows = reconcileCheckRows({
  rows: checkRows,
  yoloResults: response.yolo_results,
  ocrResults: response.ocr_results,
  guideX: 0.5,

setCheckRows(updatedRows);
```

13. OCR / YOLO の対応付け

既存の推論結果モードで実装済みの対応付けロジックを活用してください。

優先順:

1. detection.ocr_text があれば使う

2. yolo_results と ocr_results が同indexに近ければ同indexで使う

3. OCR bbox の中心点が YOLO bbox 内に入るものを紐付ける

4. Label候補の近傍左右にある Tube OCR を紐付ける

5. nmbシリーズの扱い

Label候補として、nmbシリーズの検出結果を扱ってください。

判定例:

* class_name に `nmb` を含む
* class_name に `label` を含む
* role が `label`
* role が `nmb`
* text が検査テーブル label と一致する

もし class_name がまだ返っていない場合:

* OCR text が checkRows[].label のいずれかと一致するものを Label候補とする

15. Tube候補の扱い

Tube候補として、Tube検出結果を扱ってください。

判定例:

* class_name に `tube` を含む
* role が `tube`
* role が `tube_l`
* role が `tube_r`

もし class_name がまだ返っていない場合:

* Label候補以外で、Labelの左右にあるOCR結果をTube候補として扱う
* ただし誤判定を避けるため debug log を出す
