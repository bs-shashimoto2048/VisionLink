目的:

また、OCR 前に指定された画像前処理を適用して読み取り精度を改善する。

要件1: カメラ映像中央に赤色ガイドラインを表示

1. カメラ映像の中心に、縦方向のガイドラインを表示してください。
   - カメラ表示領域の中央 x = 50% に表示
   - 検出・推論・OCR処理には影響させない
   - あくまで作業者向けの視覚ガイド

2. ガイドラインは透過性のある赤色にしてください。
   - 目立ちすぎないこと
   - 推論結果やOCR文字の視認性を邪魔しないこと

CSS例:

```css
.camera-center-guide {
  position: absolute;
  top: 0;
  bottom: 0;
  left: 50%;
  width: 2px;
  transform: translateX(-50%);
  background: rgba(255, 0, 0, 0.35);
  pointer-events: none;
  z-index: 12;
}
```

3. video / canvas / bbox overlay と同じ親コンテナ内に配置してください。

   * overlay 座標と一致するようにする
   * `position: absolute; inset: 0;` 系のカメラステージ内に置く
   * BBOX より邪魔にならない z-index にする
   * ただしカメラ映像上で見えること

4. ガイドラインはすべての表示モードで表示して構いません。

   * 通常表示
   * YOLO結果
   * OCR結果
   * 推論結果

5. ガイドラインは処理対象ではありません。

   * 画像フレームに描き込まない
   * backend へ送る frame には影響させない
   * canvas へ焼き込まない
   * DOM overlay として表示するだけにする

要件2: Rotate OCR の対象を「ガイドライン左側の Tube のみ」に限定

6. 既存の Rotate OCR ボタン状態を使用してください。

状態:

* rotateLeftTubeOcr = false

  * ボタン表示: `Rotate OCR: OFF`
  * 通常OCR

* rotateLeftTubeOcr = true

  * ボタン表示: `Rotate OCR: ON`
  * ガイドライン左側の Tube 検出 bbox のみ、OCR前に180度回転

7. Rotate OCR: ON のとき、回転対象は以下に限定してください。

対象:

* YOLOで Tube として検出された bbox
* かつ、画面中央ガイドラインより左側にある bbox

対象外:

* label
* terminal number
* 右側 Tube
* Tube 以外の class
* ガイドライン右側の bbox

8. 左側判定は、backend 側では画像幅の中心を基準にしてください。

判定例:

```python
center_x = bbox_x + bbox_w / 2
is_left_of_guide = center_x < image_width * 0.5
```

9. Tube 判定は、YOLO detection の class_name / role / side などを優先してください。

対象とみなす例:

* class_name: `tube`
* class_name: `tube_l`
* class_name: `left_tube`
* class_name: `tube_left`
* role: `tube_l`
* role: `tube`
* side: `left` かつ tube 系

対象外とみなす例:

* class_name: `label`
* class_name: `terminal`
* class_name: `number`
* role: `label`

10. class_name がない、または既存YOLOが class_name を返していない場合は、暫定実装として以下にしてください。

* class_name / role が不明な場合は Tube 判定を false にする
* ただし既存実装で tube bbox と label bbox を区別できない場合は、TODOコメントを残す
* 誤って label を回転対象にしないことを優先する

重要:
今回の要件では「labelは対象にしない」ことが重要です。
Tube と判断できない bbox を安易に回転対象にしないでください。

11. Rotate OCR: ON で回転対象になった bbox は frontend 側で紫色にしてください。

条件:

* rotated=true
* または role/side 情報から rotate対象と判断できるもの

表示:

* 通常 bbox: 既存色
* Rotate対象 bbox: 紫色

12. backend の OCRResult には rotate 情報を返してください。

例:

```json
{
  "text": "K12345",
  "confidence": 0.91,
  "bbox": [0.12, 0.34, 0.18, 0.04],
  "source": "paddleocr",
  "rotated": true,
  "rotation_deg": 180,
  "side": "left",
  "role": "tube"
}
```

非回転:

```json
{
  "text": "POA9S8",
  "confidence": 0.89,
  "bbox": [0.62, 0.34, 0.18, 0.04],
  "source": "paddleocr",
  "rotated": false,
  "rotation_deg": 0,
  "role": "tube"
}
```

15. 前処理は ai_pipeline.py に関数として分離してください。

例:

```python
def preprocess_ocr_crop(crop: np.ndarray, config: dict | None = None) -> np.ndarray:
    ...
```

16. 前処理の適用順は以下を基本にしてください。

推奨順:

1. crop_margin optional
2. deskew optional
3. grayscale
4. CLAHE
5. denoise
6. sharpen
7. stroke_boost
8. gamma optional
9. threshold
10. morph optional
11. resize

ただし、OCR精度や画像型の都合で順序調整が必要な場合は、コメントを残した上で調整して構いません。

17. ratio_threshold の扱い:

* crop の横縦比 `width / height` を計算する
* ratio_threshold = 1.6
* 横長の場合は `resize.wide_height = 64` を使って高さ64に合わせる
* それ以外は `resize.single = 64` を基準にする
* keep_ratio = true の場合、縦横比を維持してリサイズする

18. threshold:

* type = binary
* value = 90
* grayscale画像に対して `cv2.threshold(gray, 90, 255, cv2.THRESH_BINARY)` を適用
* PaddleOCR / TextRecognition が二値画像よりRGB/BGRを期待する場合は、最後に3chへ戻す

19. CLAHE:

* clip_limit = 2
* tile_grid_size = 2
* `cv2.createCLAHE(clipLimit=2, tileGridSize=(2, 2))`

20. sharpen:

* enabled = true
* amount = 1
* sigma = 2
* Gaussian blur 差分で sharpen してください

例:

```python
blurred = cv2.GaussianBlur(image, (0, 0), sigma)
sharpened = cv2.addWeighted(image, 1 + amount, blurred, -amount, 0)
```

21. stroke_boost:

* enabled = true
* method = close
* ksize = 1
* iterations = 1
* ksize=1 は効果が小さいが、設定通り実装してください
* 必要ならコメントで「効果が弱い場合は ksize=2 or 3 を検討」と残す

22. denoise:

* method = gaussian
* ksize = 1
* ksize=1 は実質効果が少ないが、設定通り実装してください
* cv2.GaussianBlur を使う
* ksize が1以下の場合はスキップしてもよいが、ログまたはコメントで分かるようにする

23. deskew:

* enabled = true
* 可能であれば簡易deskewを実装してください
* 文字領域の傾きを推定できない場合は、安全に元画像を返してください
* deskew失敗でOCR全体が落ちないようにしてください

24. disabled の前処理も、将来ONにできるよう関数だけ用意するか、設定を読んでスキップできる構造にしてください。

対象:

* gamma
* morph

25. 前処理後の画像を OCR に渡してください。

処理順:

* crop 作成
* Rotate対象なら 180度回転
* OCR前処理
* PaddleOCR / TextRecognition 実行

重要:
Rotate対象の場合は、先に180度回転してから前処理してください。
理由:
反転後の文字向きに対して deskew / resize / threshold を適用したいため。

26. 前処理は検出やYOLO推論には影響させないでください。

* YOLO detection は元画像で実施
* BBOX座標も元画像基準のまま
* 前処理は OCR crop のみに適用
